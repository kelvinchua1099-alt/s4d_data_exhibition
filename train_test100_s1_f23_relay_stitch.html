History head v2 vs Point4D head · 23 帧两块接力（3D 交接）+ 块间 Sim(3) 拼接 · 测试集 100 段

同一批 100 段测试集（和 48 帧接力页同一份数据、同样的第 0 帧 query），取连续 23 帧（0.77 s）。两个 step 24000 的模型都切成 2 块接力：块长 13 帧、相邻块共享 3 帧（块 0 = 帧 0–12，块 1 = 帧 10–22），每块独立前向。主行按 Point4D track_long_video 的3D 交接：用共享帧的深度云估块间 Sim(3)，把块 0 在帧 10 上预测的 3D 点直接搬进块 1 当起点；灰色行有 48 帧页的像素交接（只传投影像素、块 1 从像素重新起步）作对照。两块的输出各在自己的第 0 帧相机系，打分前用 3 个共享帧上的预测拟合一次 RANSAC Sim(3) 把块 1 拼到块 0 上，拼成一条后整段一次 RANSAC Sim(3) 对齐到 GT——这才是不借助 GT 的接力结果。另有每块各自对齐到 GT、整段 23 帧一次前向两种对照。每段可开 3D 查看器看 3D 交接拼接后的两条轨迹。

约定

项约定
数据4RC/data/s4d_test100_s1_f48 的前 23 帧（源帧 0–22 连续，1280×720）：和 s1 / s5 / s10 页同一份 100 段划分（test100_same.txt）；query 点 = 第 0 帧前景 mask 内每 4 像素取 1 个，真值轨迹表达在第 0 帧相机系、米制
切块照 Point4D track_long_video 切块：stride = 块长 − 共享帧数 = 10，块 0 = 帧 0–12、块 1 = 帧 10–22；共享帧 10–12 的最终预测归块 0（不做 Point4D 的重叠区加权混合）
3D 交接（主行）照 Point4D track_long_video（论文算法 1）：块 1 先前向一次拿深度云（dense_head 深度 + camera_head 相机反投影到块 1 第 0 帧相机系，H/8 × W/8 网格，不依赖 query）；共享帧 10–12 上同一网格像素的两块深度云配对，用 Point4D 的 _chunk_sim3（按配对距离取最小的 85%、Umeyama 带尺度闭式解）估块 0 → 块 1 的 Sim(3)；块 0 在帧 10 上预测的 3D 点经它搬到块 1 第 0 帧相机系，作为块 1 的起点 3D（模型的 query_coords，链 / 直接 query 都从它出发）再前向一次；query 像素是这些 3D 用块 1 第 0 帧预测内参的投影、裁到画内（eval_point_track_relay.py --handoff xyz）。和原版的差别：原版的外观 patch 沿用第 0 块出生处缓存的那份，这两个模型每块从自己第 0 帧的 query 像素处裁 patch，所以块 1 的 patch 取自投影像素
像素交接（对照）同 48 帧页：块 0 在帧 10 上的预测 3D 用 camera_head 预测的该帧相机投影成像素、裁到画内，作为块 1 的 query 像素；块 1 从这个像素重新起步（History v2 = 自己的 self-query 估 3D，Point4D head = dense_head 深度在该像素反投影），不传 3D。这是 Point4D 附录 D 给 2D 基线用的 First-frame 策略，不是 Point4D 自己的做法
块间拼接（打分）两种交接都一样：块 0 不动；块 1 的预测在帧 10–12 上和块 0 的预测逐点配对（全部点·帧，两边都有限的才用），拟合一次 Sim(3)（RANSAC：1000 次随机 3 点、内点 5 cm、内点精化，>16384 对先抽 16384；5 cm 是模型输出单位，不是米），用它把块 1 整块搬到块 0 第 0 帧相机系，填帧 13–22（rescore_point_track.py --stitch）。只用模型自己的预测，不碰 GT
模型History head v2 · step 24000：History head 消融新架构重训（xyz 档 (−2, 8) + composition loss）。Point4D head · step 24000：原版 Point4D sparse query head 接同一 VGGT-Omega backbone、同等步数的消融（ablation/point4d_head.py）。每块看 13 帧（训练是 12 帧）；整段对照是 23 帧一次前向（约训练长度的 2 倍）
打分4RC track_eval.py 口径：avg_pts = 误差在 0.1 / 0.3 / 0.5 / 1.0 m 内的比例取平均，dyn 只算总运动 > 0.01 m 的点；EPE 全部点·帧平均。全部用 RANSAC Sim(3)（同正式评测）：拼接行整段一次；逐块对 GT 行每块各自一次（块 1 借了 GT 的尺度和位姿，是拼接做到完美时的参照）；整段一次行整段一次。survival 同 PIPs++ 口径，用同一组对齐投影到 GT 相机。RANSAC 的 3 点抽样没设种子（estimate_sim3 里是 default_rng()，seed 42 只管 >16384 时的抽样），同一批预测每次打分都不同，单段 avg_pts 能差到 0.5，所以汇总表另给 5 次重复打分的均值 ± std
3D 查看器白底，GT（黑）与两个模型 3D 交接 + 块间拼接后的轨迹（整段一次 RANSAC Sim(3) 对齐到 GT，和主行打分同一种对齐），每段最多 300 条（等距抽样）、GT 相机视锥，第 0 帧相机系；可按模型 / 轨迹着色、拖尾、逐帧、只画 100 / 30 / 10 条、误差连线，右下角是逐帧平均误差曲线（帧 13 起是块 1）。接力评测没存深度图，所以没有点云；逐块对 GT 的预测两块不在同一坐标系，不进查看器

拼接诊断

块间尺度 = 打分时块 1 → 块 0 的轨迹 RANSAC Sim(3) 尺度；尺度出界 = 它 <0.5 或 >2 的段（拼接塌掉）；拼接残差 = 拼好后共享帧上两块预测的距离中位数 ÷ 块 0 第 0 帧预测深度中位数；块 1 损失 = 每段块 1 的 avg_pts（拼接 − 逐块对 GT）；深度云 Sim(3) = 3D 交接时用深度云估的块 0 → 块 1 尺度。裁到画内 = 交接时 query 像素投到画外被裁回的比例。

像素交接时第 2 块为什么差

像素交接下 Point4D head 的块 1 在交接后第一帧就从 0.717 掉到 0.524（逐块对 GT 也一样），而整段一次前向在同样的帧上几乎不掉，所以不是看不了 23 帧，是块 1 的起点错了。诊断：交接像素本身偏了约 20 px（真值像素帧 0→10 的位移中位数是 43 px，交接误差约是它的一半），两个模型偏得差不多；把块 1 的 query 换成帧 10 的真值像素（relay_oracle_handoff.py，其余不变）后 Point4D head 的块 1 基本回到块 0 的水平。差别在起步方式：Point4D head 的起点 = dense_head 深度在 query 像素处反投影，像素偏到人物轮廓外就取到背景深度；History v2 的 self-query 从像素特征自己估 3D，对偏差宽容得多。3D 交接直接把 3D 点搬进块 1，绕开了这一步。
