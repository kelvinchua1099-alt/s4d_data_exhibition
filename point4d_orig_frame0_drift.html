原版 Point4D 权重 · 第 0 帧起点误差与跨块拼接漂移

原版 Point4D（Point4D/checkpoints/point4d_final.pt，DA3 backbone，没在 s4d 上训过）的长视频追踪 track_long_video 分两步：先用第 0 帧预测深度在 query 像素处反投影得到 3D 起点，再分块解码、块间用共享帧的深度云估 Sim(3) 把 3D 点交接给下一块并拼成一条。这页分别检查这两步：起点本身有多准（对照我们在 s4d 上训到 step 44000 的 Point4D head 与 History v2），以及 100 帧连续视频按块长 12 / 重叠 3 切成 11 块、拼过 10 条接缝后，越往后的块漂多远（对照不拼接的整段 100 帧一次前向，以及两个头同样的 12/3 接力）。

约定

项约定
模型原版 Point4D 官方权重，输入 294×518，backbone 双向（起点能看到整块）。对照：s4d_train 上训到 step 44000 的 Point4D head 消融（起点 = dense_head 第 0 帧深度反投影）和 History head v2（起点 = self-query；拼接部分用深度起点版 history_abl_v2_step44000_depth，两头起点同口径）
第 0 帧 · 数据s4d_test100_s1 与 s4d_test100_s5_f12 各 100 段测试集，第 0 帧是同一张图，区别只在同一块里的另外 11 帧（连续取 / 每 5 帧取 1）。query = 第 0 帧可见的前景点，4RC 评测原样（每 4 像素一个）
第 0 帧 · 起点全块：12 帧一起编码后在第 0 帧深度上反投影，就是 track_long_video 里 query 的 xyz；单目：只把第 0 帧一张图送进 backbone；head0：同一次全块编码，decoder 以全块起点为 query 解码目标帧 0（= 正式评测预测的第 0 帧，自检相对差中位 6e-07）。两个头取正式评测预测的第 0 帧
第 0 帧 · 对齐与指标每段只用第 0 帧的点做一次 Sim(3)（RANSAC：5 cm 内点、1000 次、固定种子；另报闭式最小二乘），avg_pts0 = 误差在 0.1 / 0.3 / 0.5 / 1 m 内的比例取平均，逐段平均。中位误差和比例是 100 段全部点池化。轮廓圈：query 网格上缺 4 邻居之一的点（前景 mask 最外一圈，占 17.6% 的点）。偏远：对齐后点的 z 比真值大（落到了真值后面，多半取到背景深度）。AbsRel / δ<1.25 只看第 0 帧相机系 z，逐段按中位数缩放，和 K、对齐都无关
拼接 · 数据s4d_test100_s1_f100：同一批 100 段的连续 100 帧（前 48 帧与 48 帧接力页逐点一致）
拼接 · 推理原版 track_long_video 原样，只把 LongTrackConfig 设成块长 12 / 重叠 3（README 默认 64/16，100 帧只切 2 块）：块 k 覆盖帧 [9k, 9k+12)，共 11 块；交接时用共享帧上 1024 个网格像素的两块深度云、按 85% 分位剔点后 Umeyama 估块间 Sim(3)，把上一块在交接帧的 3D 预测搬进下一块当 query，外观 patch 沿用第 0 帧；输出用累计 Sim(3) 的逆搬回第 0 块第 0 帧相机系，共享帧按位置从前一块线性过渡到后一块。两个头的 12/3 接力是同样的 3D 交接 + 深度云 Sim(3) 拼接（拼接在打分阶段做），结果沿用 point_track_relay_f100_c12o3_xyz_dstitch
拼接 · 打分整段一次：100 帧全部点一次 RANSAC Sim(3) 对齐到 GT（4RC 口径：>16384 点抽样、5 cm 内点；这里固定种子），avg_pts 同上。逐块各自：按同样的切块（共享帧归前一块）每块单独对齐到 GT，去掉块间拼接误差，作上界。漂移：第 k 块的单独对齐相对第 0 块的单独对齐差多少——尺度比 sk/s0、旋转角、以及第 k 块的预测点分别套两种对齐后的距离中位（米，即"拿第 0 块的对齐去看第 k 块会偏多远"）。不拼接对照：原版整段 100 帧一次前向（块长 100），同样按 12/3 切块算逐块对齐和漂移，量的是预测本身随时间的变形；12/3 拼接比它多出来的部分才是拼接带来的。整段 100 帧一块的解码耗时 ≈ 点数 × 帧数 × 块长，全部点要约 2.5 小时，所以这一组每段固定种子抽 500 个 query 点只算这些点；下面的汇总、曲线和接缝表四组都限制在这同一批 500 点上（全部点的 avg_pts 另列一列）

结论

原版的第 0 帧起点不如两个头。12 帧全块反投影（track_long_video 的起点）第 0 帧 avg_pts0 0.712（s5_f12 0.718），低于 Point4D head 0.785 和 History v2 0.866；逐段输给两者 79:15 和 94:4。双向全块比只喂第 0 帧（0.660）高 0.05，但在 s4d 上训过带来的提升更大。head 在第 0 帧的输出（0.715）基本就是复现反投影点。

起点误差集中在前景轮廓，而且偏远。轮廓圈只占 17.6% 的点，原版 >1 m 的误差却有 61% 落在这一圈，轮廓圈中位误差 0.40 m，内部只有 0.033 m；>0.3 m 的误差里 71% 对齐后落在真值后面（取到了背景深度），Point4D head 也是 73%，History 只有 37%。换最小二乘对齐，除 History（0.840）外都掉到 0.5–0.6，是这些飞点把对齐拉偏了。

原版按 12/3 拼 10 条接缝会明显漂移，而且越拼越远。同一批 500 点上，12/3 拼接的 100 帧 avg_pts 0.348，整段 100 帧一次不拼接 0.428，低 0.08（逐段 69:29）。前 3 块两者差不多（偏移中位 0.28 / 0.45 / 0.62 m vs 不拼接 0.25 / 0.34 / 0.41 m），从第 4 块起拼接误差开始累积：到末块（帧 91–99）偏移 2.89 m vs 1.12 m，旋转 65° vs 23°，尺度比 0.67 vs 0.96。拼接多出来的主要是尺度：每过一条接缝平均缩 4%（块间 Sim(3) 是用共享帧上两块的深度云估的，推测是相邻两块深度的尺度对不齐、每次交接都偏小一点），不拼接时尺度基本不变。

不拼接的整段一次也在变形，所以漂移不全是拼接造成的。同样按 12/3 切块看，100 帧一次前向的第 1 块相对第 0 块已经偏 0.25 m、旋转 10°，到末块 1.12 m、23°；逐块各自对齐比整段一次高 0.11（12/3 拼接是 0.14）。100 帧也超过了 README 默认的块长 64。

自身漂移比拼接漂移大，拼接主要放大后半段、带来尺度漂移。逐段配对看，前 4 块（到帧 47）拼接只多 0.04–0.13 m，自身已偏 0.25–0.45 m；最后 3 块拼接多 0.68–0.99 m，和自身的 1.10–1.22 m 相当。尺度漂移几乎全来自拼接（自身末块 0.96，拼接后 0.67）。按 avg_pts，自身漂移代价 0.11，块间拼接只多 0.03，另 0.05 来自短块块内精度（见拆分表）。

两个头同样 12/3 接力漂得少得多。同一批点上 Point4D head / History v2 拼接后 avg_pts 0.580 / 0.507（原版 0.348），末块偏移 0.68 / 0.88 m、旋转 16° / 21°、尺度比 0.99 / 0.89，偏移比原版不拼接的整段一次还小；拼接代价 0.06 / 0.07。也就是说，在 s4d 上训过之后，同样的 3D 交接 + 深度云 Sim(3) 拼接不再是主要的误差来源。
