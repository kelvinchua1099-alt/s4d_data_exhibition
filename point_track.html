Point Tracking · 4RC

从 S4D 通过质量门槛的视频段里随机抽 100 段，转成 TAPVid-3D 格式，跑 4RC 自带的 sparse 点追踪评测：第 0 帧的人物前景点作为 query，追踪它们在之后 63 帧（约 8.4 秒）的 3D 位置。每段视频左边是网格真值轨迹，右边是 4RC 的预测。

评测协议

评测脚本和参数与 4RC 仓库的 eval/track/eval_point_track.sh 一致，只把数据换成 S4D。真值由 S4D 的逐帧网格顶点给出，不是标注或估计。

项约定
抽样从 1110 段过门槛的段（世界 × 相机）里固定种子随机抽 100 段；去掉与无群众版同路线的 3 群众重跑批和工业区；第 0 帧看不到人的段跳过补位
帧源视频 30 fps，从第 0 帧起每 4 帧取 1 帧，共 64 帧（约 8.4 s）；视频按 7.5 fps 播放即为实时速度
query 点第 0 帧人物 mask 内每 4 个像素取 1 个，按深度反投影到 3D；主角、群众、车都算前景
真值轨迹每个 query 点挂到最近的网格三角形上，随网格逐帧搬运（三角形三顶点的加权 Procrustes）；到网格距离中位数 0.06 到 0.19 cm
模型输入64 帧 RGB 缩放到 504×280，一次前向；模型对第 0 帧每个像素输出它在每一帧的 3D 位置，评测在 query 像素上取值
打分整段所有点、所有帧一起做一次 Sim(3) RANSAC 对齐，误差在 0.1 / 0.3 / 0.5 / 1.0 m 以内的比例取平均为 avg_pts；后续帧被遮挡的点照样计分

分组结果

avg_pts 为官方逐段结果的平均；EPE 列是可视化脚本重新做 Sim(3) 对齐后的逐段平均误差再取中位数（RANSAC 未固定种子，与官方数值有小差异）。各阈值内比例（全部 100 段平均）：0.1 m 内 0.095，0.3 m 内 0.231，0.5 m 内 0.314，1.0 m 内 0.434。

说明

画面方向。转换沿用数据引擎上游的相机约定，几何对齐的是左右镜像后的图像，所以 4RC 看到的输入是镜像画面；这里的视频画完点后整体翻回正向。

T-pose 开头。抽到的 96 个世界里有 6 个（Namaqualand 4、Ancient2 2）主角在第 0 帧还是 T-pose 或接近 T-pose，要过 4 到 30 帧才进入正常步态；这些段的 query 点取在 T-pose 上，真值轨迹本身是对的。

贴近相机的点。跟拍相机在窄处会被推到离身体很近，离相机不到 0.1 m 的点不画，拖尾里单段超过 120 像素的跳变也不画，只影响画面，不影响打分。

评测于 2026-10-07，权重 Luo-Yihang/4RC，--num_frames 64 --size 512 --align sim3。视频 1280×360（两个 640×360 面板），H.264。
