约定

项约定
数据4RC/data/s4d_test100_s10：s4d_train 测试集抽 100 段，源帧 0, 10, …, 110 共 12 帧。帧号 1 起算：第 1–9 帧 = 源帧 0–80，第 10–12 帧 = 源帧 90–110
前景点4RC 点追踪评测的 query 点：第 0 帧前景 mask 内每 4 像素取 1 个，真值随网格搬运，第 0 帧相机系、米。每帧只取该帧真值可见且投影在画面内的点（被挡的点在深度图上看到的是遮挡物，无从评 dense_head）
dense_headcheckpoint train/epoch022-step00050000.pt（全量微调，带 depth loss），一次 12 帧前向。该帧深度图在真值像素处双线性采样，按 camera_head 预测的内参反投影、按其预测的位姿搬到第 0 帧相机系，和 3D 查看器里的深度点云同一套，不含真值
motion_head同一次前向的链式轨迹在这些点、这些帧上的位置（与对比页 s4d_train 的输出相同，纯推理）。第 1 帧是它的 self-query 输出（只看像素给出的 3D 位置）
对齐与打分每段、每个区间、每个方法各自把区间内所有帧的点放在一起做一次 Sim(3) RANSAC，再用 4RC 的 compute_average_pts_within_thresh：avg_pts = 误差在 0.1 / 0.3 / 0.5 / 1.0 m 内的比例取平均；逐帧数值用所在区间的那组对齐拆开算。各段等权平均
注意dense_head 是在真值像素位置取深度，只考深度和相机，不用自己找对应；motion_head 要自己把点追到这一帧。所以 dense_head 分数相当于"已知 2D 位置时"的 3D 精度，不是一个追踪器的分数。motion_head 的数值也和对比页的 avg_pts 不同：这里只算可见点、按区间对齐。第 1–9 帧前面的帧可见点多，区间对齐由它们主导。4RC 的 RANSAC 不播种，同一输入重跑单段会抖 ±0.03 左右
