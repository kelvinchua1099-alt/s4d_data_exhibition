s4d_train vs 4RC / Point4D · 测试集 100 段 · 每 10 帧取 1 帧

从 s4d_train 的测试集划分（360 段、212 个世界，世界与训练集不重叠）里固定种子抽 100 段，每段从源帧 0 起每 10 帧取 1 帧、共 12 帧（30 fps → 3 fps，约 3.7 s）。三个模型吃同样的 12 帧，用 4RC 的 sparse 点追踪评测打分，每段可开 3D 查看器看 GT 与三条对齐后的预测轨迹，并叠加 s4d_train 自己预测的逐帧深度点云。

100测试段（92 个世界，跟拍 50 / 静态 50）
12帧 / 段（源帧 0, 10, …, 110）
74s4d_train 单段最佳的段数
3001平均 query 点数 / 段

约定

项约定
抽样splits/test.txt 的 360 段固定种子 0 打乱后按顺序转换，第 0 帧前景点不足 50 的段跳过（2 段），凑满 100 段；同一世界的两台相机可能都被抽中
帧源帧 0, 10, 20, …, 110，共 12 帧，1280×720。和 train 页的 12 帧对比（sample100，源帧 0–44、步长 4）不是同一份数据，分数不能跨页比
query 点第 0 帧前景 mask 内每 4 像素取 1 个，按深度反投影；真值轨迹按最近三角形随网格搬运，表达在第 0 帧相机系，米制
s4d_traincheckpoint train/epoch022-step00050000.pt，纯推理：不给真值 query 3D、不给真值相机，链从模型自己对 query 像素的 3D 估计出发，下一跳位置用 camera_head 预测的相机投影；输入缩到 512×288。训练时相邻帧的源帧间隔是 15–20，这里是 10
4RC / Point4D同 四模型对比页：4RC 输入 512 长边 patch 14，第 0 帧每像素逐帧 3D；Point4D 输入 518×294，track_long_video 单块
打分4RC 的 track_eval.py：整段所有点所有帧一次 Sim(3) RANSAC 对齐，avg_pts = 误差在 0.1 / 0.3 / 0.5 / 1.0 m 内的比例取平均；dyn 只算总运动 > 0.01 m 的点；seed 42
survivalPointOdyssey / PIPs++ test_on_pod.py 的 survival rate：3D 预测按上面同一组 Sim(3) 对齐后用 GT 相机投影成 2D，坐标归一到 256×256，一条轨迹从第 0 帧起"活着"，第一次在 GT 可见帧上偏离 > 16 px 就算死、之后都算死（GT 被挡的帧不判死，投到相机后方算死），所有轨迹所有帧"活着"的比例 × 100（compute_survival.py）
3D 查看器白底，GT（黑）与各模型 Sim(3) 对齐后的轨迹，每段最多 300 条（等距抽样）、GT 相机视锥，坐标系为第 0 帧相机系，可按模型 / 轨迹着色、拖尾、逐帧。深度点云：s4d_train 同一次前向里 dense_head 的逐帧深度按 camera_head 预测的内参反投影、再按其预测的相机位姿搬到第 0 帧相机系（H/8 × W/8 网格，按输入图像着色），用和它轨迹相同的那组 Sim(3) 对齐到 GT，默认累积到当前帧（0..t 帧叠在一起），可切回只看当前帧、开关、调点大小。不含任何真值，和 s4d_train/vis/visualization.py 的 viser 查看器画的是同一份东西
