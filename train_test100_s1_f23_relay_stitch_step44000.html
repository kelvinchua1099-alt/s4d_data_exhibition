History head v2 vs Point4D head · 23 帧两块接力（3D 交接）+ 块间 Sim(3) 拼接 · 测试集 100 段

同一批 100 段测试集（和 48 帧接力页同一份数据、同样的第 0 帧 query），取连续 23 帧（0.77 s）。两个 step 44000 的模型都切成 2 块接力：块长 13 帧、相邻块共享 3 帧（块 0 = 帧 0–12，块 1 = 帧 10–22），每块独立前向。主行按 Point4D track_long_video 的3D 交接：用共享帧的深度云估块间 Sim(3)，把块 0 在帧 10 上预测的 3D 点直接搬进块 1 当起点。两块的输出各在自己的第 0 帧相机系，打分前照 Point4D 的拼法把块 1 拼到块 0 上：块间 Sim(3) 就是共享帧深度云估的那个（交接和拼接用同一个），取逆把块 1 搬到块 0 的坐标系，共享帧从块 0 平滑过渡到块 1；拼成一条后整段一次 RANSAC Sim(3) 对齐到 GT——这才是不借助 GT 的接力结果。另有每块各自对齐到 GT、整段 23 帧一次前向，以及旧版拼接（用共享帧上的轨迹点拟合块间 Sim(3)）作对照。每段可开 3D 查看器看 3D 交接拼接后的两条轨迹。

约定

项约定
数据4RC/data/s4d_test100_s1_f48 的前 23 帧（源帧 0–22 连续，1280×720）：和 s1 / s5 / s10 页同一份 100 段划分（test100_same.txt）；query 点 = 第 0 帧前景 mask 内每 4 像素取 1 个，真值轨迹表达在第 0 帧相机系、米制
切块照 Point4D track_long_video 切块：stride = 块长 − 共享帧数 = 10，块 0 = 帧 0–12、块 1 = 帧 10–22；拼接行的共享帧 10–12 照 Point4D 默认的 overlap_strategy="smooth" 混合：帧 10 取块 0、帧 11 两块各半、帧 12 取块 1；逐块对 GT 行和旧版拼接行的共享帧归块 0
3D 交接（主行）照 Point4D track_long_video（论文算法 1）：块 1 先前向一次拿深度云（dense_head 深度 + camera_head 相机反投影到块 1 第 0 帧相机系，H/8 × W/8 网格，不依赖 query）；共享帧 10–12 上同一网格像素的两块深度云配对，用 Point4D 的 _chunk_sim3（按配对距离取最小的 85%、Umeyama 带尺度闭式解）估块 0 → 块 1 的 Sim(3)；块 0 在帧 10 上预测的 3D 点经它搬到块 1 第 0 帧相机系，作为块 1 的起点 3D（模型的 query_coords，链 / 直接 query 都从它出发）再前向一次；query 像素是这些 3D 用块 1 第 0 帧预测内参的投影、裁到画内（eval_point_track_relay.py --handoff xyz）。和原版的差别：原版的外观 patch 沿用第 0 块出生处缓存的那份，这两个模型每块从自己第 0 帧的 query 像素处裁 patch，所以块 1 的 patch 取自投影像素
块间拼接（打分）照 Point4D track_long_video：块 0 不动；块 0 → 块 1 的 Sim(3) 用共享帧 10–12 上两块深度云（同一网格像素配对，_chunk_sim3）估——就是交接用的那一个；取逆把块 1 整块搬到块 0 第 0 帧相机系，帧 13–22 取块 1，共享帧按上面的权重混合（rescore_point_track.py --stitch --stitch_mode point4d）。只用模型自己的预测，不碰 GT。旧版拼接（灰色行，这页之前的主行）：块 1 的轨迹点在帧 10–12 上和块 0 的轨迹点逐点配对拟合 RANSAC Sim(3)（1000 次随机 3 点、内点 5 cm、内点精化，--stitch_mode tracks）——只有前景点、而且把两块轨迹在共享帧上的差异吸收进对齐里，不是 Point4D 的做法
模型History head v2 · step 44000：History head 消融新架构重训（xyz 档 (−2, 8) + composition loss）。Point4D head · step 44000：原版 Point4D sparse query head 接同一 VGGT-Omega backbone、同等步数的消融（ablation/point4d_head.py）。每块看 13 帧（训练是 12 帧）；整段对照是 23 帧一次前向（约训练长度的 2 倍）
打分4RC track_eval.py 口径：avg_pts = 误差在 0.1 / 0.3 / 0.5 / 1.0 m 内的比例取平均，dyn 只算总运动 > 0.01 m 的点；EPE 全部点·帧平均。全部用 RANSAC Sim(3)（同正式评测）：拼接行整段一次；逐块对 GT 行每块各自一次（块 1 借了 GT 的尺度和位姿，是拼接做到完美时的参照）；整段一次行整段一次。survival 同 PIPs++ 口径，用同一组对齐投影到 GT 相机。RANSAC 的 3 点抽样没设种子（estimate_sim3 里是 default_rng()，seed 42 只管 >16384 时的抽样），同一批预测每次打分都不同，单段 avg_pts 能差到 0.5，所以汇总表另给 5 次重复打分的均值 ± std
3D 查看器白底，GT（黑）与两个模型 3D 交接 + 块间拼接后的轨迹（整段一次 RANSAC Sim(3) 对齐到 GT，和主行打分同一种对齐），每段最多 300 条（等距抽样）、GT 相机视锥，第 0 帧相机系；可按模型 / 轨迹着色、拖尾、逐帧、只画 100 / 30 / 10 条、误差连线，右下角是逐帧平均误差曲线（帧 13 起是块 1）。接力评测没存深度图，所以没有点云；逐块对 GT 的预测两块不在同一坐标系，不进查看器

拼接诊断

块间尺度 = 拼接时块 1 → 块 0 的尺度（深度云拼接 = 深度云 Sim(3) 的倒数，旧版 = 轨迹点 RANSAC Sim(3)）；尺度出界 = 它 <0.5 或 >2 的段（拼接塌掉）；拼接残差 = 块 1 搬过去后（混合前）共享帧上两块轨迹预测的距离中位数 ÷ 块 0 第 0 帧预测深度中位数（旧版是在这些点上拟合的，残差天然小）；块 1 损失 = 每段块 1 的 avg_pts（拼接 − 逐块对 GT）。裁到画内 = 交接时 query 像素投到画外被裁回的比例。
