motion_head 位置编码 · octave 置零与周期混叠

s4d_train 链式头的 3D query 坐标经 xyz_embed（15 档傅立叶特征）进模型，self-query 的像素经 uv_embed（8 档）。这里逐个把一档的 sin/cos 置零，看每一跳的 3D 误差涨多少，在干净输入和带噪输入下各测一次；再查实际输入坐标会不会超出最低档的周期。

k ≤ 4起作用的 xyz 档：k ≥ 5 置零每跳 |Δ| ≤ 0.03（×1e-3）
+21.0置零 k=0 的误差增量，干净输入各跳平均（×1e-3，基线 23.0）
69 → 107带噪输入本身的误差：第 1 跳 → 第 11 跳（×1e-3）
1.8%训练 GT 的 z 落在任意宽 2 窗口外的比例（会和窗口内的点编码重合）

约定

项约定
模型checkpoint outputs/train/epoch022-step00050000.pt（主 run，全量微调 50000 步）。xyz_embed：3 轴 × 15 档，第 k 档是 sin/cos(2k·π·x)，周期 21−k，k = 0 周期 2、k = 14 周期 1.2e-4；之后过 Linear 和 LayerNorm。uv_embed：2 轴 × 8 档，同样的频率，只在 self-query 用
数据测试划分 splits/test.txt 的 360 段（每个世界 × 相机取第一个起点），S4DDataset 原生 512×288、12 帧 11 跳、global 归一化（第 0 帧场景平均距离 = 1），和训练同一口径；每段第 0 帧前景 mask 内随机取 256 个点
置零在 proj 的输入处把第 k 档所有轴的 sin 和 cos 都乘 0（forward_pre_hook），其余档不动。Δ = 置零后误差 − 不置零误差
每跳单独测跳 s → t 的输入固定，只在这一跳置零，误差不沿链累积。干净：输入 = 第 s 帧的 GT 位置（逐跳 teacher forcing）。带噪：输入 = 不置零时纯推理链（query_coords=None，从 self-query 起步）在第 s 帧的累积预测，也就是推理时这一跳实际吃到的输入；不置零时这一列就是推理链本身的误差（脚本里有断言核对）
误差第 t 帧输出和 GT 的 L2 距离，归一化单位（不做 Sim(3) 对齐），一段的 256 个点取平均，再在 360 段上取平均；± 是跨段标准误。表里数值都 ×1e-3
注意置零不是均值消融：低档的 cos 在数据上的均值不是 0，置零会额外把输入推到没见过的分布，k = 0、1 的增量里有这部分。高档 sin/cos 在数据上近似零均值，置零和"去掉这档信息"等价

结论

只有最低 4–5 档在起作用。干净输入下置零 k = 0 误差增加 +19.1 ~ +28.8（基线 16.6 ~ 26.6，即 +72% ~ 173%），k = 1 增加 +6.2 ~ +7.4，k = 2 约 2，k = 3 不到 1，k = 4 不到 0.2，k ≥ 5 不到 0.03，k ≥ 8 不到 0.001。proj 权重按档的列范数也是这样：初始化（trunc_normal std 0.02）每档约 1.57，训练后 k = 0 长到 3.09，k = 4 降到 0.69，k ≥ 9 都在 0.12 左右，是初始化的 1/13。单靠 weight decay（0.05，lr ≤ 1e-4，约 5.3 万步）最多缩到 0.77 倍，所以高频档是训练主动压下去的。uv_embed 也一样，k = 1（周期 = 一个画面宽）最重要，k ≥ 5 置零没有影响。

带噪输入下，低档的绝对贡献不变，中频档变成轻微的负贡献。推理链的输入本身就偏了 69（第 1 跳，即 self-query 误差）到 107（第 11 跳），约是干净输入下每跳误差的 4 倍。k = 0、1 置零的增量和干净时差不多（+18.2 ~ +28.5、+6.3 ~ +8.9）；k = 2 从约 2 降到 +0.2 ~ +1.8；k = 3–6 在前 5 跳反过来，置零后误差略降（k = 4 为 -0.20 ~ -0.11，3–5 个标准误）。也就是噪声在 0.07 左右时，周期 0.25–0.06 的档读到的已经是噪声。不过量级不到基线的 0.5%，实际可以忽略。

频率个数不是瓶颈，最低档才是要注意的地方。去掉 k ≥ 5 的档，对这个 checkpoint 不会有可测的影响（真要改得重训确认）；对噪声敏感的中频档影响不到 0.5%。模型最依赖的 k = 0 正好是周期为 2、会混叠的那一档，见下面的周期混叠。

周期混叠

所有档的周期 21−k 都能整除 2，所以整段编码对每个轴都以 2 为周期：x 和 x + 2 的编码完全相同，模型没法从 xyz_embed 区分它们。编码是所有段共用的，所以要看的是全部输入的范围，不只是单段的跨度：一段里 z = 2.3 的点，在模型看来和另一段里 z = 0.3 的点是同一个位置。下表推理侧取已存预测里链式头每一跳的输入（第 0..T−2 帧输出，第 0 帧 = self-query），消融头取它唯一的输入，即第 0 帧深度反投影点；训练侧取 S4DDataset 训练划分随机 300 段的 GT（第 0..10 帧）。

不能整个划掉，也不是只有长序列流式才会出现。12 帧训练数据里就有：10/300 段单段跨度超过 2，z 有 1.8%、x 有 0.8% 的输入落在任何一个宽 2 的窗口外，它们的编码和窗口内某个位置完全重合。帧间隔越大越多（s5 24 帧覆盖 115 个源帧，z 有 4.8%）。主要发生在 z 上：global 归一化只让第 0 帧场景平均距离 = 1，远处的前景点 z 能到 2–4；消融头第 0 帧深度点 z 最大到 4，14–18% 的段单段跨度就超过 2（少数落在 mask 边缘、取到背景深度的点）。y 轴从没超过。

uv_embed（2D）不会混叠：uv 归一化到 [0, 1]，跨度不超过 1，小于最低档周期 2。

可改的方向（都要重训）：加更低的档（start_octave = −1 或 −2，周期 4 或 8）；编码前把坐标缩小；或者编码相对第 0 帧 query 位置的坐标、再拼上原始坐标。哪种更好，这里没有测。
